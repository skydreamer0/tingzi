# 語音浮窗遷移到 Tauri

文件版號 `0.1.0`。本文件說明語音浮窗從 .NET WinForms 遷移到 Tauri 2（Rust 後端加網頁介面）的範圍、階段與完成條件。新程式放在 `app/`；遷移完成前，安裝包仍使用 `windows/float/` 的現有浮窗。

## 為什麼遷移

- **Codex 辨識內建**：現有浮窗每次辨識都啟動一個外部的 `codex-asr.exe`，每次都重新建立連線。`codex-asr` 本身是 Rust 函式庫，新程式直接把它編進來，整個執行期間共用一條連線。同一段 5 秒錄音實測：外部執行檔每次約 1.0 到 1.7 秒；內建後第一次約 1.0 秒，之後約 0.8 秒。
- **介面**：設定與浮窗改用網頁技術排版，深淺色、圓角、動畫都由 CSS 處理，不必自己繪製每個控制項。
- **執行環境**：不再需要使用者另外安裝 .NET 8 桌面執行環境；Windows 11 已內建 WebView2。

## 不遷移的部分

注音輸入法是 Windows 文字服務（TSF），必須是載入到各應用程式裡的原生 DLL，維持 C++，不在這次遷移範圍。

## 架構

| 位置 | 職責 |
| --- | --- |
| `app/src-tauri/src/audio.rs` | 用預設麥克風錄音，輸出 16 kHz 單聲道 WAV。 |
| `app/src-tauri/src/recognise.rs` | 透過內建的 `codex-asr` 送出辨識，把服務錯誤轉成使用者看得懂的訊息。 |
| `app/src-tauri/src/deliver.rs` | 簡繁轉換、寫入剪貼簿、貼到錄音開始時的視窗。 |
| `app/src-tauri/src/settings.rs` | 讀取現有浮窗存的 `voice-settings.json`，兩個程式共用同一份偏好。 |
| `app/src-tauri/src/main.rs` | 錄音狀態、全域快捷鍵、系統匣、與介面之間的事件。 |
| `app/ui/` | 浮窗介面（HTML、CSS、JavaScript），只顯示狀態，不處理錄音或辨識。 |

## 階段

**階段 0：第一條流程（已完成）**

- 按快捷鍵或麥克風開始錄音，再按一次停止。
- 用內建的 Codex 辨識，結果依設定轉成繁體或簡體。
- 依「辨識完成後」的設定，貼到原本的視窗、只複製，或只顯示。
- 沿用現有的錄音快捷鍵與輸出設定。

**階段 1：與現有浮窗對等**

- 錄音途中換欄時不自動貼入，保留預覽。
- 系統匣選單：辨識音檔、編輯與複製辨識文字、剪貼簿簡繁轉換、切換到注音。
- 語音結果套用自訂詞。
- 收合到螢幕邊緣的麥克風、拖曳位置、多螢幕。
- Codex 草稿的 Ctrl＋Alt＋V 貼入。
- 完成條件：現有 `VoiceDelivery` 測試涵蓋的每個情境，新程式都有對應測試並通過。

**階段 2：設定頁**

- 四個分頁（語音輸入、注音與工具、外觀與啟動、關於）改用網頁介面。
- 色系、強調色、登入啟動、麥克風選擇與測試。
- 自訂詞、文字範本、學習資料的管理。

**階段 3：本機辨識**

- 模型常駐記憶體，支援顯示卡，切掉前後靜音。
- 作為線上辨識失敗時的備援，以及不想上傳錄音時的選項。

**階段 4：取代現有浮窗**

- 安裝包改帶新程式，注音服務改為啟動新程式。
- 移除 `windows/float/` 與 .NET 執行環境的需求。
- 完成條件：從 0.6 升級後，設定、自訂詞、範本與學習資料都保留。

## 開發與測試

```bash
cd app/src-tauri
```

```bash
cargo test
```

```bash
cargo build --release
```

現有浮窗還在執行時，兩個程式會搶同一組錄音快捷鍵。開發時先設定環境變數 `TINGZI_RECORD_KEY` 為另一個字母（例如 `T`），新程式就改用該字母，輔助鍵不變。

`Tingzi.exe --transcribe 音檔.wav` 可以不開視窗，直接檢查內建的辨識是否能用。

## 已知限制

- 線上辨識使用這台電腦上 Codex 的登入狀態，並把錄音送到第三方服務；`codex-asr` 是非官方的用戶端。
- 新程式目前只有浮窗，沒有設定頁；偏好仍要在現有浮窗的設定裡改。
- 尚未加入安裝包，也沒有簽章。
