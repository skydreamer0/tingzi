# 選字基準測試

這個資料夾量測注音引擎選字選得好不好：把每一句的注音一鍵一鍵打進新的組字區，看預覽出來的文字是不是想要的那一句，同時記錄每按一鍵要等多久。GitHub Actions 的 Windows 工作流程每次都會跑，結果顯示在該次執行的摘要頁。

| 檔案 | 用途 |
| --- | --- |
| `sentences.tsv` | 測試句。每行是「類別、想要的文字、實際按下的注音、說明（可省略）」，以 Tab 分隔。 |
| `baseline.tsv` | 每個類別目前答對的句數、字數，以及選錯的字有幾個在第一頁就改得到。任何一項少於這個數字時測試失敗。 |
| `benchmark.cpp` | 量測程式，由 `windows/test_engine.cmd` 編譯與執行。 |
| `annotate.py` | 幫忙寫測試句：由文字推出最常見的讀音。 |

## 類別

| 類別 | 內容 |
| --- | --- |
| `general` | 日常對話。 |
| `medical` | 醫療用語。 |
| `mixed` | 中英混合。英文字照原樣通過，前後的中文各自是一段組字，和實際打字時一樣。 |
| `homophone` | 容易選錯的同音詞，例如「權利／權力」「公式／公事」。 |
| `long` | 四、五十個音節的長句，主要看長句時每鍵的延遲。 |
| `typo` | 打錯的注音：近音（ㄓ／ㄗ、ㄣ／ㄥ 等）、聲調打錯，以及按到隔壁的鍵。「想要的文字」是使用者原本要打的字，「注音」是他實際按下的。 |
| `fast` | 快打時按鍵的順序：音節前加 `^` 表示聲調鍵比最後一個注音早按，音節後加 `!` 表示一聲字後面沒按空白鍵。 |

## 看結果

每個斷詞模式（`path` 是預設的整句最高分，`staged` 是分批定案）各跑一次，每個類別列出：

- **整句答對**：預覽和想要的文字完全相同的句數。
- **逐字答對**：以編輯距離算出的正確字數。
- **第一頁就改得到**：選錯的字當中，正確的字出現在該位置候選清單第一頁（或按 Tab 切到的近音字清單第一頁）的比例。打錯注音的句子，這一欄代表使用者能不能很快改回來。
- **每鍵延遲**：按鍵加上重新算出預覽的時間，列出中位數、第 95 百分位與最慢的一鍵。第 95 百分位超過 20 ms 或最慢超過 250 ms 時測試失敗。

結果後面列出每一句沒打對的句子，方便找出是哪一類錯誤。

## 改了引擎之後

1. 在 Windows 上執行 `windows\test_engine.cmd`，或推送分支讓 CI 跑。
2. 某個類別變差，測試會失敗並列出差多少；先看「沒打對的句子」找原因。
3. 某個類別變好，輸出會出現 `BETTER`。把 `.build\engine-test\baseline.tsv`（這次的結果）複製成 `windows\bench\baseline.tsv`，在同一個 commit 提交，之後就不會再退回去。

## 新增測試句

測試句要自己造，不要抄錄有著作權的文章或別人的私人文字。

```powershell
python windows/bench/annotate.py <放 phrases.txt 的資料夾> < 新句子.txt
```

輸入每行是「類別、Tab、文字」，輸出可直接貼進 `sentences.tsv`。讀音取詞庫裡最常見的一個，多音字（了、的、得、行、長、重、還、和等）一定要人工確認，並照台灣一般人實際打字的讀法寫。`typo` 類別要手動把注音改成打錯的樣子，並在說明欄寫出錯在哪裡。

加了句子之後，基準數字一定會變，記得一起更新 `baseline.tsv`。
