# 語音浮窗遷移到 Tauri

文件版號 `0.3.0`。本文件說明語音浮窗從 .NET WinForms 遷移到 Tauri 2（Rust 後端加網頁介面）的範圍、階段與完成條件。新程式放在 `app/`；自 0.7.0 起安裝包改帶新程式，原本的 `windows/float/` 已移除。

## 為什麼遷移

- **Codex 辨識內建**：0.6 的浮窗每次辨識都啟動一個外部的 `codex-asr.exe`，每次都重新建立連線。`codex-asr` 本身是 Rust 函式庫，新程式直接把它編進來，整個執行期間共用一條連線。同一段 5 秒錄音實測：外部執行檔每次約 1.0 到 1.7 秒；內建後第一次約 1.0 秒，之後約 0.7 到 0.8 秒。
- **介面**：設定與浮窗改用網頁技術排版，深淺色、圓角、動畫都由 CSS 處理，不必自己繪製每個控制項。
- **執行環境**：不再需要使用者另外安裝 .NET 8 桌面執行環境；Windows 11 已內建 WebView2。

## 不遷移的部分

注音輸入法是 Windows 文字服務（TSF），必須是載入到各應用程式裡的原生 DLL，維持 C++，不在這次遷移範圍。鍵盤切換與學習工具也維持原樣，新程式透過安裝資料夾裡的執行檔呼叫它們。

## 架構

| 位置 | 職責 |
| --- | --- |
| `app/src-tauri/src/main.rs` | 錄音、辨識、取消的流程；全域快捷鍵、系統匣、與介面之間的事件。 |
| `app/src-tauri/src/audio.rs` | 用選定的麥克風錄音，切掉前後靜音，輸出 16 kHz 單聲道 WAV；把匯入的 WAV 轉成同一格式。 |
| `app/src-tauri/src/recognise.rs` | 線上辨識（內建 `codex-asr`）與本機辨識（呼叫這台電腦上的 Whisper 程式）。 |
| `app/src-tauri/src/deliver.rs` | 簡繁轉換、追蹤錄音開始時的視窗、複製與貼入的規則。 |
| `app/src-tauri/src/words.rs` | 自訂詞與文字範本的讀寫，以及用自訂詞校正同音字。 |
| `app/src-tauri/src/codex.rs` | 判斷鍵盤是否在 Codex 桌面版的訊息框，供 Ctrl＋Alt＋V 使用。 |
| `app/src-tauri/src/layout.rs` | 浮窗的三種形狀（收合、橫條、編輯）與位置記憶。 |
| `app/src-tauri/src/panel.rs` | 設定視窗的讀取與儲存、麥克風測試、學習資料與自訂詞的管理。 |
| `app/src-tauri/src/settings.rs` | 偏好檔 `voice-settings.json`，格式與現有浮窗相同。 |
| `app/src-tauri/src/instance.rs` | 單一執行個體，以及第二次啟動或注音服務傳來的要求。 |
| `app/src-tauri/src/dialogs.rs`、`paths.rs` | Windows 的選檔與確認對話框；安裝資料夾與個人資料夾的位置。 |
| `app/ui/` | 浮窗（`index.html`）與設定頁（`settings.html`），只顯示狀態與收集選擇。 |

## 貼入的規則

文字只貼到錄音開始時鍵盤所在的地方：

- 錄音開始時記下前景視窗、所屬程式與有游標的控制項。點浮窗自己的麥克風會把鍵盤移到浮窗，這時改用移開前的最後一個位置，貼入前再把鍵盤交還。
- 錄音到貼入之間只要切到別的視窗，就不貼入；文字留在浮窗的編輯區，並已複製到剪貼簿。
- 目標是標準 Windows 文字方塊（例如記事本）時直接寫入該控制項，不經剪貼簿；其餘程式用剪貼簿加 Ctrl＋V。
- 貼入前確認剪貼簿仍是剛寫入的文字；被其他程式改過就不貼。
- 已知限制：瀏覽器和 Electron 程式整個視窗只有一個控制項，同一視窗內換欄位無法偵測，文字會貼到目前游標所在的欄位。

## 階段

**階段 0：第一條流程（已完成）**

- 按快捷鍵或麥克風開始錄音，再按一次停止；用內建的 Codex 辨識，依設定轉成繁體或簡體，貼到原本的視窗。

**階段 1：與現有浮窗對等（已完成）**

- 上述貼入規則；辨識中點麥克風可取消。
- 系統匣選單：設定、找回浮窗、錄音、辨識音檔、編輯與複製辨識文字、剪貼簿簡繁轉換、切換到注音、本機學習開關、收合、結束。
- 語音結果套用自訂詞。
- 收合成螢幕右緣的麥克風（右鍵展開）、拖曳後記住位置、位置落在不存在的螢幕時拉回畫面內。
- 有辨識文字時，在 Codex 訊息框按 Ctrl＋Alt＋V 貼入。
- 現有 `VoiceDelivery` 測試的每個送字情境，在 `deliver.rs` 都有對應測試。

**階段 2：設定頁（已完成）**

- 四個分頁（語音輸入、注音與工具、外觀與啟動、關於）；色系、強調色、登入啟動、麥克風選擇與測試。
- 自訂詞與文字範本的新增、刪除、匯入、匯出；學習資料的開關、匯入、匯出、清除。
- 儲存後浮窗立即套用新的快捷鍵、色系與字級。

**階段 3：本機辨識（部分完成）**

- 已完成：切掉錄音前後的靜音；線上辨識失敗時保留錄音，點麥克風改用本機辨識；設定可選只用本機辨識，不上傳錄音。
- 未做：模型常駐記憶體與顯示卡加速。目前每次辨識仍啟動一次 Whisper 程式。

**階段 4：取代現有浮窗（已完成，0.7.0）**

- 安裝包改帶新程式，沿用 `TingziFloat\TingziFloat.exe` 的位置與名稱，注音服務與開始功能表捷徑不必改。
- 移除 `windows/float/`、`windows/tests/` 與 .NET 執行環境的需求。
- 浮窗靜止時的按鈕改用產品標誌；錄音與辨識時才換成狀態圖示。
- 建置時重新對應原始碼路徑，執行檔不含建置電腦的資料夾名稱；打包時收錄每個 Rust 相依套件的授權檔，沒附授權檔的套件改附標準授權全文（`windows/licenses/`）。
- 升級後登入啟動會改指向新版本的資料夾；設定、自訂詞、範本與學習資料都保留。

## 開發與測試

```bash
cd app/src-tauri
```

```bash
cargo test
```

```bash
cargo build --release
```

- 設定環境變數 `TINGZI_RECORD_KEY` 為一個字母（例如 `T`）再啟動開發版，它會改用該字母當錄音鍵，並使用另一組執行個體名稱，可以和已安裝的版本同時執行。
- 程式執行中時，再執行一次並加上 `--show`、`--settings`、`--edit` 或 `--open-wav 音檔.wav`，要求會交給執行中的那一份。
- `Tingzi.exe --transcribe 音檔.wav` 不開視窗，直接檢查線上辨識；加上 `--local` 改用本機辨識。

## 已知限制

- 線上辨識使用這台電腦上 Codex 的登入狀態，並把錄音送到第三方服務；`codex-asr` 是非官方的用戶端。
- 麥克風以名稱辨認；0.6 以裝置代碼辨認，升級後若偏好檔裡的麥克風名稱對不上，請到設定重新選一次。
- 語音浮窗需要 Microsoft Edge WebView2 Runtime；Windows 11 內建，少數 Windows 10 需要另外安裝。
- 安裝包沒有簽章。
